## 2. Предварительная дорожная карта

Это предложение последовательности, а не утверждение технических решений или полного состава первой версии. Каждый пункт — первый небольшой эксперимент с указанной возможностью. Пункты можно переставлять и делить по пояснениям пользователя. Не начинать следующий шаг до подтверждения текущего.

| Шаг | Эксперимент | Наблюдаемый результат | Состояние |
|---|---|---|---|
| 01 | Правила, концепция и карта демо | В новом чате можно восстановить назначение проекта и продолжить с правильного места | Подготовлено, ожидает проверки |
| 02 | Минимальная оболочка веба и простой бэкенд | Приложение открывается в браузере; навигация видна; один демонстрационный запрос связывает веб с сервером; неготовые разделы явно обозначены | Предложено |
| 03 | Первый редактор источника | В разделе выбранного протокола можно заполнить форму и увидеть созданную настройку; протокол и поля уточняются перед реализацией | Предложено |
| 04 | Демонстрационный драйвер и хаб | Имитатор выдаёт метрики, а веб показывает их значения, качество и необходимые метаданные; нет заявления о поддержке реального протокола | Предложено |
| 05 | Один шаблон формы | Шаблон заполняет поля; инженер редактирует их и получает самостоятельную настройку | Предложено |
| 06 | Первая компоновка дашборда | Можно собрать небольшую страницу из простых элементов и выбранных данных; источники не становятся собственностью страницы | Предложено |
| 07 | Первый редактор SVG | Можно создать простую мнемосхему и разместить её на странице; проверяем один небольшой сценарий редактора | Предложено |
| 08 | Первый сценарий событий | Понятны настройка одного демонстрационного события и его отображение в диспетчере | Предложено |
| 09 | Проект как рабочее пространство | Можно объединить дашборды и представление событий без обязательного распределения устройств по проектам | Предложено |
| 10 | Каталог и один демонстрационный модуль | Видно, как добавленная возможность появляется в приложении; реальное и имитируемое поведение управления модулем обозначено | Предложено |
| 11 | Один скриптовый сценарий | Установленная демонстрационная возможность правил позволяет настроить и проверить простую автоматизацию | Предложено |
| 12 | Необязательная история | Историю можно включить для небольшого примера и показать график; текущие данные доступны и без неё | Предложено |
| 13 | Первый сценарий личной страницы, настроек и диагностики | Уточнено содержимое личной страницы; важные настройки и сведения о работе уже созданных возможностей доступны через веб | Предложено |

Каталог не обязан ждать реализации всех предыдущих возможностей: порядок можно поменять. Ранний шаблон шага 05 может быть встроенной демозаготовкой, а затем появиться как материал каталога. Это не создаёт зависимости уже сохранённых настроек от шаблона.

При развитии стенда проверяем универсальность на подходящих примерах, включая виртуальные/составные источники и задачи вне готовой СКАДА. Не нужно одновременно разрабатывать несколько законченных отраслевых приложений.

## 4. Карта страниц

**Реализованных страниц и URL пока нет.** Ниже — планируемые назначения, а не существующие маршруты. После реализации добавлять фактический адрес, основной файл, источник данных и проверенные действия.

| Страница/раздел | Предварительное назначение |
|---|---|
| Личная страница | Представление данных конкретного пользователя; состав ещё предстоит объяснить |
| Настройки | Веб-доступ к настройкам платформы и её возможностей |
| Диагностика | Сведения о фактической работе уже созданных частей демо |
| Устройства | Общий вход; отдельные подразделы для протоколов и их редакторов |
| Дашборды | Список, просмотр и редактор компоновки страниц |
| Мнемосхемы | Работа с SVG в отдельном редакторе |
| Правила | Редактор скриптов и их использование при наличии движка |
| События | Настроенные события/аварии и их представление; детали уточняются на примере |
| Проекты | Подбор дашбордов и событий для рабочего пространства |
| Каталог | Дополнения, установленные возможности, шаблоны и обновления |

Неподготовленные страницы в будущем каркасе могут быть честно обозначенными заглушками. Заглушка не считается реализацией функции.

## 5. Карта серверного поведения и данных

**Бэкенд ещё не реализован.** Нет выбранного хранилища, API, портов, схем данных или готовых драйверов. Ниже перечислены вопросы для будущих экспериментов, а не утверждённые сервисные границы.

| Возможность | Что нужно будет показать в демо |
|---|---|
| Настройка источников | Как форма передаёт настройки и как затем пользователь видит/меняет результат |
| Драйвер и хаб | Как источник предоставляет данные и как потребители получают нужный поток |
| Метрики | Какие значения, качество и метаданные нужны конкретному сценарию |
| Шаблоны | Откуда берётся заготовка и как она однократно заполняет форму |
| Дашборды, SVG и проекты | Как сохраняется результат работы редактора и используется в другом представлении |
| События, скрипты, история | Что создаётся пользователем, что возникает во время работы и какие возможности необязательны |
| Каталог | Как пользователь меняет состав доступных возможностей и видит результат |

Для реализованного участка здесь нужно кратко указывать: назначение; путь к исходникам; входные и выходные данные; фактические маршруты/способ обмена; где и как долго живут данные; какая страница их использует; что имитируется. Не восстанавливать всё это каждый раз по вёрстке и не дублировать документацией каждую функцию кода.

## 6. Упрощения, запуск и проверки

На шаге 01 работающих имитаторов тоже нет: подготовлена только документация. Позднее каждая имитация отмечается рядом с реализованной возможностью. Например, видимые данные генератора не означают поддержку реального SNMP или Modbus.

Сейчас сборка, запуск, автоматические тесты и команды установки зависимостей отсутствуют. Не предлагать npm install или запуск сервера до появления соответствующих файлов.

Проверка шага 01: три MD-файла находятся по ожидаемым путям, русский текст читается, относительные ссылки между документами открываются, концепция отражает последние уточнения пользователя. Служебные файлы репозитория не меняются.

## 7. Ближайшая работа и открытые вопросы

Следующий кандидат — шаг 02. Его цель: небольшой запускаемый веб с понятной оболочкой и один простой бэкенд, чтобы дальше добавлять поведение по объяснениям пользователя. Остальные разделы пока можно показать как неготовые. На этом шаге выбирается простой стек и появляются точные команды запуска.

Не решены конкретный вид навигации, состав личной страницы, поля первой формы протокола и способ компоновки редактора. Не требуется закрыть все эти вопросы перед началом оболочки; уточнять их в соответствующем эксперименте, не выдавая технические заглушки за окончательный продукт.

Переход к проектированию настоящей архитектуры — отдельный последующий этап после достаточного прояснения поведения. Конец этой предварительной таблицы сам по себе не означает, что все требования уже исследованы.
