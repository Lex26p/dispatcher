# Пользователи и права доступа

## Общий принцип

Проект является одной из основных областей разграничения доступа, но права не должны ограничиваться только проектами.

Система должна поддерживать роли или группы прав, а также собственные наборы прав без жёсткой привязки к фиксированным ролям «оператор/инженер/администратор».

## Основные уровни прав

Концептуально различаются:

- просмотр;
- управление;
- редактирование и настройка;
- административные действия.

Один пользователь может иметь разные права в разных проектах.

Права должны последовательно действовать во всём приложении: если пользователь не имеет доступа к данным или устройству, они не должны становиться доступны через другой Dashboard или интерфейс.

## Режим управления

Режим управления является дополнительной защитой от случайных действий.

Он доступен только пользователю, у которого уже есть право управления.

Логика:

- нет права управления — режим управления включить нельзя;
- есть право управления — пользователь может включить режим управления, если этот механизм используется в системе;
- после заданного времени режим может отключаться автоматически.

Режим управления не обязан быть включён как обязательное правило во всех проектах.

## Значимые действия

Значимые действия пользователя должны фиксироваться системой и при необходимости отображаться в диспетчере событий.

## Понятность интерфейса

Если действие недоступно, интерфейс должен по возможности объяснять причину: недостаточно прав, требуется включить режим управления и т. п.
