# Проекты

## Назначение

Проект — самостоятельная точка консолидации элементов системы.

Чаще всего проект будет соответствовать отдельной локации или объекту, но это не является жёстким требованием.

Проект используется для:

- логического объединения нужных элементов системы;
- навигации;
- представления информации;
- разграничения доступа.

## Проект не является владельцем

Дашборды, мнемосхемы, устройства, автоматизации и другие элементы существуют независимо от проекта. Проект связывает их в нужный контекст, но не создаёт отдельные экземпляры сервисов.

Один Dashboard может использоваться в нескольких проектах.

Для других типов элементов возможность использования в нескольких проектах определяется отдельно в соответствующей концепции.

Для устройств это решение принято в `CORE-006`: одно устройство может использоваться в нескольких проектах. Такая связь задаёт контекст представления и доступа, но не делает Project владельцем Device и не создаёт копию устройства. Метрики, принадлежащие устройству, следуют project-context связям устройства; самостоятельные метрики могут иметь собственные project-context связи.

## Проекты не вложены друг в друга

Проект не может содержать другой проект. Иерархия проектов не используется.

## События нескольких проектов

Изоляция проектов не должна заставлять пользователя постоянно переключаться между ними.

Пользователь, имеющий доступ к нескольким проектам, должен иметь возможность видеть единый поток доступных ему событий и фильтровать его по проектам.

## Dashboard проекта

Проект может использовать один или несколько Dashboard. Один из связанных Dashboard может быть выбран как стартовый.

## Контекст и параметры

Проект может передавать параметры и контекст используемым Dashboard. Это позволяет переиспользовать один Dashboard в разных проектах с разными настройками.

Конкретные механизмы передачи параметров описываются в концепциях Dashboard и мнемосхем.

## Работа в Web UI

Для проектов используется общий для системы подход: список проектов и редактор проекта.
