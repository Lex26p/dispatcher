# Диспетчер событий

## Назначение

Диспетчер событий — единый глобальный сервис, отображающий значимые события, аварии, предупреждения, действия пользователей и системные проблемы.

События из разных источников должны находиться в одном временном потоке, чтобы пользователь мог проследить цепочку происходящего.

## Событие

Событие — значимое изменение или факт, произошедший в системе.

Источником может быть:

- оборудование;
- метрика;
- пользователь;
- сама платформа;
- установленный плагин.

## Аварии и обычные события

Обычные события и аварии отображаются в одном сервисе, но концептуально отличаются.

Обычное событие обычно является единичным фактом. Авария может иметь жизненный цикл: возникла, подтверждена, устранена.

Не все события требуют подтверждения.

## Уровни важности

События могут иметь уровни важности, позволяющие отделять информационные сообщения от предупреждений и критических аварий.

Точный набор названий уровней будет определяться позже.

## Проекты

Диспетчер событий не создаётся отдельно для каждого проекта.

Проект является контекстом и фильтром. Пользователь с доступом к нескольким проектам может видеть единый поток доступных ему событий без постоянного переключения между проектами.

## Действия пользователей

Значимые действия пользователя могут попадать в общий поток: выполнение команды, изменение уставки, подтверждение аварии, изменение критичной настройки и подобное.

Каждый клик по интерфейсу событием не является.

## Плагины

Плагины должны иметь возможность публиковать свои значимые события в общий диспетчер. Пользователь не должен работать с отдельным журналом для каждого установленного модуля.
