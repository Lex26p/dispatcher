# Dashboard

## Роль

Dashboard — универсальная пользовательская страница и базовый строительный механизм Web UI системы.

Это не только панель показателей. Dashboard может использоваться для операторских экранов, информационных страниц, системных страниц и других интерфейсов, если задача естественно решается его средствами.

Специализированный интерфейс создаётся только там, где Dashboard для задачи недостаточен.

## Контейнерная модель

Dashboard строится из контейнеров и компонентов.

Контейнеры могут содержать другие контейнеры, что позволяет формировать структуру страницы без отдельного специализированного механизма для каждой компоновки.

Примеры компонентов:

- мнемосхема;
- текст;
- изображения;
- значения;
- кнопки;
- таблицы;
- компоненты, добавленные плагинами.

## Компоновка

Предпочтителен смешанный подход с уклоном в Web: контейнеры, строки, колонки, размеры, выравнивание и адаптивность. Там, где это оправдано, допускается более свободное размещение.

Dashboard может использовать адаптивную компоновку или фиксированный размер операторского экрана.

## Параметры и контекст

Dashboard может:

1. ничего не передавать вложенному компоненту;
2. самостоятельно задавать параметры компоненту;
3. получать параметры от проекта и делегировать их вложенному компоненту;
4. сочетать параметры разных уровней.

Общий принцип:

> Каждый уровень может передавать контекст нижестоящему уровню, но передача не является обязательной.

Dashboard также может передавать параметры при переходе на другой Dashboard или при открытии модального Dashboard.

## Переиспользование

Один Dashboard может использоваться в нескольких проектах. Изменение общего Dashboard отражается везде, где используется тот же Dashboard. Если нужна независимая версия, создаётся отдельная копия.

## Навигация и модальные окна

Dashboard может:

- открывать другой Dashboard;
- открывать модальный Dashboard;
- использовать вкладки и другие контейнерные элементы компоновки.

Модальные окна являются возможностью Dashboard, а не мнемосхемы.

## Редактор

Dashboard должен иметь визуальный редактор с drag-and-drop, изменением размеров, вложением контейнеров, выбором компонентов и настройкой свойств.

Создание обычного Dashboard не должно требовать HTML/CSS/JavaScript.

## Пользовательское состояние

Временное состояние просмотра — выбранная вкладка, фильтр, масштаб, последний выбранный элемент и подобное — может сохраняться индивидуально на стороне пользователя/браузера. Оно не должно изменять общий Dashboard для других пользователей.

## Режим управления

Пользователь с правом управления может при необходимости включать временный режим управления. Это дополнительная защита от случайных действий.

Режим управления может автоматически отключаться через заданное время и не обязан использоваться во всех системах.
