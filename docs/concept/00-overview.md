# Концепция проекта «Диспетчер»

## Назначение

«Диспетчер» — универсальная модульная платформа для мониторинга состояния и управления физическими и цифровыми объектами.

Независимо от предметной области система работает с текущими данными, состояниями, событиями и управляемыми значениями. Различия конкретных систем выносятся в драйверы и плагины, а ядро остаётся универсальным.

CCTV, СКУД и другие предметные системы рассматриваются как отдельные доменные модули над единым диспетчерским ядром.

## Основная модель продукта

Ядро должно оставаться небольшим и универсальным. Дополнительные функции устанавливаются только тогда, когда они нужны.

Примеры расширений:

- автоматизация;
- история;
- CCTV;
- СКУД;
- драйверы конкретных протоколов;
- отчёты;
- специализированные компоненты Dashboard;
- предметные модули.

Если пакет не установлен, его функции не должны занимать место в интерфейсе.

## Пользователи

Система предназначена одновременно для инженеров и программистов.

Типовые действия должны быть доступны через понятный графический интерфейс. Для сложной и нестандартной логики программист должен иметь полноценные инструменты.

> Простота для инженера не должна достигаться ценой ограничения программиста. Мощность для программиста не должна делать программирование обязательным для инженера.

## Граница документации

Концепция фиксирует продукт и пользовательские сервисы. Общая архитектура фиксируется отдельно в `docs/architecture/`.

Конкретные API, схемы БД, классы, очереди, форматы сообщений, deployment и другие детали реализации определяются после отдельного обсуждения.
