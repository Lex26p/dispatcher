# Концепция проекта «Диспетчер»

## Назначение

«Диспетчер» — универсальная модульная платформа для мониторинга состояния и управления физическими и цифровыми объектами.

Общая идея: независимо от предметной области система работает с текущими данными, состояниями, событиями и командами управления. Различия конкретных систем выносятся в драйверы и плагины, а ядро остаётся универсальным.

Платформа не должна позиционировать CCTV, СКУД и другие предметные системы как разновидности SCADA. Правильнее рассматривать их как отдельные доменные модули над единым диспетчерским ядром.

## Основная модель продукта

Ядро должно оставаться небольшим и универсальным. Дополнительные функции устанавливаются только тогда, когда они нужны.

Примеры расширений:

- автоматизация;
- история;
- CCTV;
- СКУД;
- драйверы конкретных протоколов;
- отчёты;
- специализированные компоненты Dashboard;
- предметные модули.

Если пакет не установлен, его функции не должны занимать место в интерфейсе.

## Пользователи

Система предназначена одновременно для инженеров и программистов.

Типовые действия должны быть доступны через понятный графический интерфейс. При этом программирование не является нежелательным или ограниченным режимом: для сложной и нестандартной логики программист должен иметь полноценные инструменты.

Ключевой принцип:

> Простота для инженера не должна достигаться ценой ограничения программиста. Мощность для программиста не должна делать программирование обязательным для инженера.

## Текущая граница этапа

На текущем этапе фиксируется только концепция продукта и сервисов ядра. Архитектура, API, базы данных, внутренние протоколы, классы, очереди, фреймворки и языки реализации будут обсуждаться позже.
