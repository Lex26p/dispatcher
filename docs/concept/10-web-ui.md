# Общая концепция Web UI

## Базовый каркас

Основной экран состоит из:

- глобального Header;
- навигации;
- рабочей области;
- панели свойств;
- Footer только там, где он действительно нужен.

Главный приоритет — рабочая область. Интерфейс вокруг неё не должен отнимать лишнюю высоту и ширину.

## Глобальный Header

Header должен быть компактным.

Слева находится кнопка основного меню («бутерброд») для навигации по сервисам приложения.

Справа находятся элементы, относящиеся к текущему пользователю и глобальным уведомлениям:

- колокольчик — быстрый доступ к диспетчеру событий;
- конверт — сообщения, на которые подписан пользователь и которые могут также приходить по внешним каналам;
- пользовательское меню — персональные функции и настройки.

## Интерфейс сервиса

Сервис при необходимости использует:

- собственную левую панель навигации;
- рабочую область по центру;
- правую панель свойств;
- собственный компактный Header только тогда, когда он действительно нужен.

Левая и правая панели могут сворачиваться, чтобы освобождать рабочее пространство.

Правая панель свойств должна по возможности быть универсальным паттерном для разных редакторов и сервисов.

## Второстепенные действия

Редко используемые ссылки и действия не должны постоянно находиться на виду.

Их следует размещать в контекстных меню, меню `...`, панелях свойств и дополнительных разделах.

## Единообразие

Разные сервисы должны использовать знакомые пользователю правила навигации, редактирования, сохранения и отображения свойств.

Для многих управляемых объектов естественным паттерном является «список + редактор», но это не является жёстким правилом для всех сервисов.

## Контекст проекта

Проект может задавать текущий контекст интерфейса. При переходах между сервисами этот контекст по возможности сохраняется, но пользователь должен иметь возможность перейти к глобальному представлению.

Не следует перегружать интерфейс длинными хлебными крошками, если текущий контекст и так понятен.
