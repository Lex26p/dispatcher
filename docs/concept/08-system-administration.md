# Системные данные и администрирование

## Платформа как объект наблюдения

Сама платформа должна рассматриваться как один из объектов диспетчеризации.

Основные системные показатели могут быть представлены обычными метриками:

- загрузка CPU;
- использование RAM;
- свободное место на диске;
- uptime;
- состояние компонентов;
- другие важные показатели.

Это позволяет использовать для системных данных те же механизмы Dashboard, событий и других сервисов.

## Системные события

Значимые проблемы платформы должны попадать в общий диспетчер событий: нехватка диска, ошибка компонента, проблема связи, ошибка скрипта плагина и т. п.

Технические подробные логи не нужно превращать в обычный поток событий. Логи остаются отдельным административным инструментом, а значимые проблемы из них отражаются как события.

## Системные Dashboard

Состояние платформы и многие административные страницы по возможности следует строить средствами Dashboard вместо создания большого количества уникальных Web-страниц.

Это не запрещает специализированные интерфейсы там, где они действительно нужны.

## Настройки

Системные настройки и настройки проектов концептуально разделяются.

Операторские функции и административные возможности также должны различаться правами доступа.
