# Менеджер пакетов

## Назначение

Менеджер пакетов — единая пользовательская точка управления всеми устанавливаемыми расширениями платформы.

Пакетом может быть:

- плагин;
- драйвер;
- шаблон;
- набор компонентов Dashboard;
- библиотека элементов мнемосхем;
- другое расширение.

Не следует создавать отдельные менеджеры для каждого типа пакетов.

## Основные действия

Пользователь должен иметь возможность:

- установить пакет;
- обновить;
- отключить;
- включить;
- удалить.

Отключение не должно означать удаление конфигурации пакета.

Перед удалением система должна предупреждать, если пакет используется существующими элементами системы.

## Каталог

Менеджер пакетов может выглядеть как внутренний Marketplace/каталог, но не обязан быть коммерческим магазином.

Пакет должен иметь понятную карточку: назначение, версия, автор, происхождение, требования, документация и описание добавляемых возможностей.

Следует различать официальные, сторонние и локальные/корпоративные пакеты.

## Установка

Помимо общего каталога должна быть предусмотрена ручная установка пакетов. Это важно для закрытых объектов и корпоративных расширений.

## Обновления

Через тот же сервис пользователь должен видеть обновления самой платформы и установленных пакетов.

Автоматическая установка обновлений не должна быть обязательной. Для диспетчерской системы пользователь должен контролировать момент обновления; автоматический режим может быть опцией.

## Совместимость

Пользователь не должен устанавливать пакет или обновление, которое заведомо несовместимо с текущей системой или необходимыми компонентами.

Технический механизм проверки будет определён на архитектурном этапе.

## Интеграция с UI

После установки пакет должен выглядеть естественной частью приложения и следовать общим правилам Web UI.

Если пакет не установлен, связанные с ним функции не должны занимать место в интерфейсе.
