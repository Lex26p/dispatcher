# Документация проекта «Диспетчер»

Этот файл — карта документации и основная точка входа.

## Правило источника истины

Репозиторий является источником истины проекта. Переписка используется для обсуждения, а согласованные решения фиксируются в документации.

В концептуальные документы не следует записывать неподтверждённые решения как факт. Если вопрос ещё не согласован, его лучше оставить вне основного документа до обсуждения.

## Структура

### `docs/concept/`

Согласованная концепция ядра. Здесь описывается **что представляет собой продукт и как он должен работать с точки зрения пользователя**, без архитектуры и реализации.

- [`00-overview.md`](concept/00-overview.md) — общий обзор продукта и границы ядра.
- [`01-core-principles.md`](concept/01-core-principles.md) — общие принципы ядра.
- [`02-projects.md`](concept/02-projects.md) — проекты как точки консолидации.
- [`03-dashboard.md`](concept/03-dashboard.md) — Dashboard как базовый конструктор Web UI.
- [`04-mimics.md`](concept/04-mimics.md) — мнемосхемы.
- [`05-devices-metrics-commands.md`](concept/05-devices-metrics-commands.md) — устройства, метрики и команды.
- [`06-event-manager.md`](concept/06-event-manager.md) — диспетчер событий.
- [`07-users-access.md`](concept/07-users-access.md) — пользователи, права и режим управления.
- [`08-system-administration.md`](concept/08-system-administration.md) — системные данные и администрирование.
- [`09-package-manager.md`](concept/09-package-manager.md) — менеджер пакетов.
- [`10-web-ui.md`](concept/10-web-ui.md) — общая концепция Web-интерфейса.
- [`11-core-boundaries.md`](concept/11-core-boundaries.md) — состав и границы ядра.

### `docs/plugins/`

Концепции дополнительных модулей, которые не входят в ядро.

- [`automation/concept.md`](plugins/automation/concept.md) — автоматизация, JavaScript и планировщик.

Другие плагины будут добавляться отдельными каталогами по мере обсуждения.

### `docs/context/`

Рабочий контекст, предназначенный для быстрого продолжения проекта в новом чате или другой рабочей сессии.

- [`CHAT_CONTEXT.md`](context/CHAT_CONTEXT.md) — краткая история решений, текущий статус и правила дальнейшей работы.

### `docs/architecture/`

Будущая архитектурная документация. На текущем этапе архитектура намеренно не фиксируется.

### `docs/decisions/`

Будущие документы о фундаментальных архитектурных и продуктовых решениях и причинах их принятия. Пока каталог зарезервирован.

## Уровни документации

1. **Concept** — что представляет собой продукт и его сервисы.
2. **Plugins** — отдельные расширения продукта.
3. **Architecture** — как система будет устроена технически; разрабатывается после концепции.
4. **Decisions** — почему были приняты ключевые решения.

Концепцию не следует превращать в подробное ТЗ. Детали интерфейсов, поля форм, API, БД, классы и технологии должны появляться на более поздних этапах.
