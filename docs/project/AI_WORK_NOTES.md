# Рабочие заметки AI-ассистента

**Назначение:** межтематические наблюдения и напоминания, ещё не являющиеся отдельными утверждёнными решениями.  
**Статус:** действующий журнал.

## NOTE-001. Исходная концепция является исторической базой

**Статус:** учтена.  
**Источник:** концепция редакции 2 от 4 августа 2026 года.

Исходный документ сохранён без изменений в `docs/product/BASELINE_CONCEPT_2026-08-04.md`. Более поздние документы заменяют его формулировки, в частности термин «виджет», модель минимального ядра, каталог, права, команды, аудит и страницы.

## NOTE-002. Термин «виджет» исключён из основной модели дашбордов

**Статус:** ожидает сквозной терминологической проверки.

В актуальной модели используются базовый элемент, контейнер компоновки, специализированный контейнер и шаблон. При дальнейшей работе нужно заменить старое слово «виджет» в новых документах и определить, требуется ли оно только как термин совместимости при импорте стороннего контента.

## NOTE-003. Дашборд и мнемосхема имеют независимые редакторы

**Статус:** учтена.

Нельзя добавлять инструменты рисования мнемосхем в редактор дашбордов. Контейнер мнемосхемы только отображает опубликованную сущность и может переводить в отдельный редактор.

## NOTE-004. Страницы являются механизмом проверки продуктовой модели

**Статус:** ожидает рассмотрения.

При создании прототипов страницы и мнемосхемы следует использовать для проверки сущностей, прав, качества данных, команд, аварий, контекста и производительности, а не рассматривать UI как завершающее оформление.

## NOTE-005. Матрица горизонтальных сервисов и предметных областей

**Статус:** ожидает рассмотрения.

Общие модели нужно проверять минимум на вентиляционной установке, электрическом щите, двери СКУД, пожарной зоне, камере, лифте, сервере, сетевом интерфейсе, насосе и счётчике.

## NOTE-006. Автоматизация требует отдельной сервисной концепции

**Статус:** ожидает рассмотрения.

Общая концепция уже определила полноценный JavaScript-совместимый runtime, изоляцию, capabilities, code editor, тестирование, Full/Edge-размещение, шаблоны и библиотеки. В отдельной концепции автоматизации потребуется детально определить API, developer workflow, runtime-состояния, debugging, профилирование, модель библиотек и эксплуатационную диагностику без выбора конкретного технологического движка на стадии общей концепции.

## NOTE-007. Импорт не является синхронизацией

**Статус:** учтена.

Не возвращаться к моделям external ownership, reconciliation, update/delete через импорт, хранению provenance импорта или автоматическим преобразованиям значений. Импорт — только строгий способ добавить новую конфигурацию в обычный черновик соответствующего редактора.

## NOTE-008. Глобальный поиск исключён

**Статус:** учтена.

Решение `PRD-Q151` заменено `PRD-Q300R`. Поиск и Excel-подобная фильтрация находятся в соответствующих сервисах. Не создавать отдельную универсальную поисковую подсистему без нового прямого решения пользователя.

## NOTE-009. Не откладывать функции внутри концепции

**Статус:** учтена.

Формулировки «будущий сервис», «позже добавить» и подобные не используются как способ упростить зрелую продуктовую модель. Очерёдность реализации определяется только при планировании разработки.

## NOTE-010. API — минимальная поверхность атаки

**Статус:** учтена.

Не возвращаться к модели «все API всегда открыты, безопасность только через RBAC». Публичные API включаются по группам возможностей и публикуются только на нужных сетевых интерфейсах; ненужный внешний listener/route должен отсутствовать по возможности.

## NOTE-011. Инженерная область не равна продуктовому сервису

**Статус:** учтена.

HVAC, пожарка, серверы, сети, насосы и другие области остаются полноценными областями диспетчеризации общей SCADA. Новый сервис выделяется только при собственной устойчивой предметной модели и рабочем процессе. Специализированное представление или пакет не следует автоматически называть сервисом.

## NOTE-012. Пожарка — предметный дашборд, не отдельный сервис

**Статус:** учтена.

На общем уровне пожарные системы используют обычные объекты, планы, дашборды, аварии и разрешённые команды. Сертифицированная автоматика остаётся локальным первичным контуром. Детальный предметный разбор может уточнить модель, но не следует без причины возвращать отдельный пожарный сервис.

## NOTE-013. IT и сети — диспетчеризация

**Статус:** учтена.

Серверы, коммутаторы, маршрутизаторы, AP, storage, VM, контейнеры, интерфейсы и каналы являются обычными управляемыми объектами. Топология и сетевая диагностика могут быть специализированными представлениями пакета; обязательный отдельный NMS-сервис не зафиксирован.

## NOTE-014. После общей проверки — отдельные вертикали

**Статус:** учтена.

После сквозной проверки общей концепции каждую крупную область применения нужно обсуждать отдельно и подробно. Цель — найти новые нюансы и при необходимости изменить сегодняшние границы, а не доказать заранее принятый ответ.
