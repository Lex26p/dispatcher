## 1. Текущий режим

Продолжается разработка общей продуктовой концепции зрелой универсальной модульной SCADA-платформы «Диспетчер». Дорожная карта, программная архитектура, технологический стек и код не формируются до завершения достаточного концептуального охвата и отдельного решения о планировании реализации.

## 2. Зафиксированный объём

В промежуточной редакции 2 зафиксированы:

- ранние решения `PRD-Q001–PRD-Q193`;
- пересобранный блок автоматизации: `PRD-Q194`, `PRD-Q195R–PRD-Q214R`, `PRD-Q215–PRD-Q216`;
- оперативная работа, смены и полноценный ТОиР: `PRD-Q217R–PRD-Q240R`;
- документы, база знаний и отчёты: `PRD-Q241–PRD-Q264`;
- строгая модель импорта/экспорта, шаблонов и копирования: `PRD-Q265N–PRD-Q290N`;
- упрощённые реестры, Excel-подобные фильтры и поиск внутри сервисов: `PRD-Q291R–PRD-Q304R`;
- замена прежнего решения о глобальном поиске `PRD-Q151` решением `PRD-Q300R`;
- уточнение `PRD-Q042`: импорт попадает непосредственно в черновик соответствующего редактора, отдельного сервиса импорта нет.

Суффиксы `R` и `N` используются для итоговых заменяющих вопросов после полного пересмотра предыдущего раунда. Черновые отвергнутые формулировки не считаются продуктовыми решениями.

## 3. Ключевые последние решения

### Автоматизация

Правила — полноценный программируемый слой на современном JavaScript-совместимом языке в изолированном производительном runtime с API SCADA, code editor, тестированием, ресурсными лимитами, шаблонами и библиотеками. Визуальные сценарии дополняют код, но не ограничивают возможности автоматизации.

### Оперативная работа и ТОиР

ТОиР является полноценной частью зрелого продукта, а не отложенной функцией. Оперативные задания, инциденты, дефекты и ремонтные работы остаются самостоятельными связанными сущностями. Есть «Моя работа», смены, передача ответственности, история замен, планы обслуживания, запчасти, трудозатраты и интерактивные регламенты.

### Импорт и экспорт

Импорт — строгий ввод только новой текстовой конфигурации непосредственно в обычный редактор. Он не редактирует и не удаляет существующее, не синхронизирует, не хранит происхождение и не выполняет смысловые преобразования. Синтаксическая ошибка отменяет весь файл. Экспорт существующих сущностей выполняется из отфильтрованного реестра; повторное использование конфигурации в редакторе обеспечивают шаблоны и операция создания копий с последовательностями уникальных полей.

### Реестры

Основной паттерн: навигация слева, компактная таблица общих свойств в центре, свойства выбранной сущности справа. Колонки настраиваются пользователем. Фильтрация работает из заголовков колонок по Excel-подобной модели, плюс поиск внутри текущего сервиса. Сохранённый фильтр можно открыть снова. Глобального поиска по всей SCADA нет.

## 5. Точка продолжения

Следующий общий блок обсуждения — **интеграции и публичный API**. После него остаются кибербезопасность и секреты, диагностика/backup/HA/DR, развёртывание и лицензирование, границы специализированных сервисов, локализация/доступность и предметная проверка общей модели.

Перед продолжением читать `AGENTS.md`, настоящий файл, `docs/product/PRODUCT_CONCEPT.md` и соответствующий раздел `PRODUCT_DECISIONS.md`. Не требуется восстанавливать принятые решения по истории чата.

## 6. Действующие ограничения работы

- Не использовать отменённый черновик дорожной карты.
- Не определять очередность реализации внутри продуктовой концепции.
- Не обозначать функцию «будущей» только потому, что её реализация может быть отложена: если она входит в зрелый продукт, она рассматривается сейчас.
- Не смешивать продуктовый сервис с программным микросервисом.
- Не тратить контекст на исчерпывающую проверку каждого подтверждённого коммита без причины; читать только релевантные файлы.
