# Инструкции для AI-ассистентов

**Область действия:** весь репозиторий.  
**Статус:** обязательные правила.  
**Дата актуализации:** 7 августа 2026 года.

Перед выполнением задачи необходимо прочитать этот файл, затем `docs/project/PROJECT_STATE.md`, относящиеся к задаче продуктовые документы и `docs/project/INTERACTION_PROTOCOL.md`.

## 1. Источник истины

1. Основным источником актуальных данных является репозиторий `https://github.com/Lex26p/dispatcher`.
2. Рабочая ветка одна — `master`.
3. Исходной точкой является последний полный SHA, присланный пользователем.
4. Перед содержательной работой необходимо прочитать относящиеся к задаче файлы из подтверждённого состояния. Глубина проверки должна быть соразмерна задаче: по умолчанию не тратить контекст на исчерпывающую перепроверку каждого коммита, если пользователь прислал полный SHA и нет признаков расхождения.
5. Чат является рабочим обсуждением. Долговременным проектным фактом решение становится после фиксации в репозитории.
6. При противоречии между чатом и репозиторием приоритет имеет репозиторий; противоречие сообщается пользователю.

## 2. Роли

Пользователь принимает продуктовые решения, скачивает ZIP, распаковывает его в `C:\Projects\dispatcher`, выполняет Git-команды и присылает новый SHA. Пользователь не редактирует подготовленные содержательные файлы вручную.

Ассистент читает актуальный репозиторий, ведёт обсуждение, формирует весь текст и код, поддерживает согласованность документов, готовит ZIP, выдаёт одну команду распаковки и минимальный Git-блок. Ассистент не записывает изменения в GitHub напрямую, пока пользователь явно не изменит порядок.

## 3. Формат поставки

- ZIP содержит полные итоговые версии изменяемых и новых файлов от корня репозитория.
- Дополнительного внешнего каталога и `.git` нет.
- Имя: `dispatcher-<область>-r<редакция>.zip`.
- Для удалений отдельно выдаются команды `Remove-Item`.

Команда распаковки:

```powershell
Expand-Archive -Path "C:\Users\pereverworkki\Downloads\<archive>.zip" -DestinationPath "C:\Projects\dispatcher" -Force
```

## 4. Git-команды

```powershell
Set-Location "C:\Projects\dispatcher"
git status
git add -A
git commit -m "<сообщение>"
git push
git rev-parse HEAD
```

Не добавлять без необходимости `git diff`, `git diff --check`, повторную проверку исходного SHA, ветки, pull request и лишнюю диагностику.

## 5. Обсуждение концепций

1. Концепция описывает зрелый целевой продукт без MVP и очередей реализации.
2. Крупные области разбиваются на небольшие темы и раунды вопросов.
3. Для вопроса приводятся варианты, последствия и рекомендация.
4. Пользователь может выбрать, изменить, объединить, отложить или заменить рекомендацию собственным решением.
5. Если пользователь не возражает по отдельному вопросу и переходит дальше, принимается рекомендованный вариант.
6. Прямое пользовательское уточнение имеет приоритет над ранее принятой рекомендацией и отражается как итоговая формулировка, а не параллельная версия.
7. Важные пользовательские идеи сохраняются в концепции, решениях, открытых вопросах или рабочих заметках.
8. После существенного объёма выполняется промежуточная фиксация, чтобы продолжение не требовало чтения истории чата.
9. При описании целевого продукта не использовать формулировки «позже», «в будущем» или аналогичные как способ отложить продуктовую функцию. Если функция относится к зрелому продукту, она рассматривается сейчас; очередность реализации определяется только на этапе планирования разработки.

## 6. Иерархия продуктовых документов

1. Общая продуктовая концепция.
2. Концепции крупных продуктовых и предметных сервисов.

## 7. Передача контекста

Поддерживаются:

- `docs/project/PROJECT_STATE.md`;
- `docs/project/DECISIONS.md`;
- `docs/project/OPEN_QUESTIONS.md`;

## 8. Рабочие заметки

`AI_WORK_NOTES.md` содержит межтематические связи, будущие уточнения, потенциальные противоречия, граничные сценарии и терминологические решения. Скрытые рассуждения и длинные пересказы чата туда не записываются.

## 9. Текущее ограничение

Общая продуктовая концепция находится в разработке. До её достаточной фиксации и отдельного указания пользователя не создавать дорожную карту, программную архитектуру, технологический стек или исходный код. Не использовать и не восстанавливать ранее начатую, но отменённую дорожную карту.
