# Инструкции для AI-ассистентов

**Область действия:** весь репозиторий.  
**Статус:** обязательные правила.  
**Дата первоначальной редакции:** 6 августа 2026 года.

Этот файл предназначен для любой модели или AI-ассистента, который продолжает работу над проектом «Диспетчер». Перед выполнением задачи необходимо прочитать этот файл, затем `docs/project/PROJECT_STATE.md` и `docs/project/INTERACTION_PROTOCOL.md`.

## 1. Источник истины

1. Основным источником актуальных данных является репозиторий `https://github.com/Lex26p/dispatcher`.
2. Рабочая ветка одна — `master`.
3. Конкретной исходной точкой работы является последний полный SHA коммита, присланный пользователем.
4. Перед содержательной работой необходимо прочитать относящиеся к задаче файлы именно из подтверждённого состояния репозитория.
5. Переписка в чате является рабочим обсуждением. Решение становится частью проекта только после фиксации в репозитории.
6. При противоречии между памятью чата и репозиторием приоритет имеет репозиторий. Противоречие нужно явно отметить пользователю.

## 2. Роли в рабочем процессе

### Пользователь

Пользователь:

- принимает продуктовые и организационные решения;
- отвечает на вопросы ассистента и добавляет собственные комментарии;
- не редактирует подготовленный текст или код вручную;
- скачивает подготовленный ZIP-архив;
- распаковывает архив в `C:\Projects\dispatcher`;
- выполняет предоставленный блок Git-команд;
- присылает полный SHA нового коммита.

### Ассистент

Ассистент:

- читает актуальный репозиторий;
- ведёт обсуждение и выявляет необходимые решения;
- формирует и изменяет весь текст и код;
- поддерживает согласованность файлов;
- готовит ZIP-архив с изменениями;
- выдаёт команду распаковки одной строкой;
- выдаёт минимальный блок Git-команд;
- обновляет файлы передачи состояния и рабочие заметки;
- использует присланный SHA как основу следующего изменения.

Ассистент не изменяет GitHub-репозиторий напрямую и не создаёт коммиты через API, пока пользователь явно не изменит этот порядок.

## 3. Формат поставки изменений

1. Изменения передаются ZIP-архивом.
2. В архиве пути начинаются от корня репозитория.
3. В архиве не должно быть дополнительного внешнего каталога с именем архива.
4. Каталог `.git` в архив не включается.
5. Архив содержит полные итоговые версии создаваемых или изменяемых файлов.
6. Для удаления или переименования файлов ассистент отдельно предоставляет команды `Remove-Item` перед распаковкой.
7. Имя архива имеет вид `dispatcher-<область>-r<редакция>.zip`.
8. Команда распаковки должна быть одной строкой и не должна использовать обратные кавычки для переноса строк.

Стандартный формат:

```powershell
Expand-Archive -Path "C:\Users\pereverworkki\Downloads\<archive>.zip" -DestinationPath "C:\Projects\dispatcher" -Force
```

## 4. Формат Git-команд

Если конкретное изменение не требует обязательной сборки или тестов, используется минимальный блок:

```powershell
Set-Location "C:\Projects\dispatcher"
git status
git add -A
git commit -m "<сообщение коммита>"
git push
git rev-parse HEAD
```

Не добавлять без необходимости:

- `git diff`;
- `git diff --check`;
- повторную проверку исходного SHA;
- дополнительные диагностические команды;
- ветки и pull request.

Обязательные проверки сборки или тесты добавляются только тогда, когда соответствующий код уже существует и проверка действительно нужна для конкретного изменения.

## 5. Порядок обсуждения концепций

1. Концепции описывают целевой зрелый продукт полностью.
2. На стадии концепций продукт не делится на MVP, ранние версии или очереди реализации.
3. Очерёдность написания кода будет определена позднее и отдельно.
4. Крупные сервисы разбиваются на небольшие самостоятельные темы.
5. По активной теме ассистент задаёт вопросы раундами.
6. Для каждого значимого вопроса ассистент предлагает варианты ответа, объясняет последствия и указывает рекомендуемый вариант.
7. Пользователь может выбрать вариант, изменить его, объединить варианты или дать собственный ответ.
8. После ответа ассистент проверяет согласованность и при необходимости задаёт дополнительные вопросы.
9. Количество вопросов не ограничивается.
10. Решение не считается принятым только потому, что ассистент его рекомендовал. Требуется явное согласие пользователя либо однозначный пользовательский ответ.

## 6. Передача контекста между моделями

Чтобы продолжение не зависело от истории чата, ассистент обязан поддерживать:

- `docs/project/PROJECT_STATE.md` — текущую точку работы;
- `docs/project/DECISIONS.md` — принятые решения;
- `docs/project/OPEN_QUESTIONS.md` — нерешённые вопросы;
- `docs/project/AI_WORK_NOTES.md` — межтематические заметки, риски и напоминания.

Новая модель должна иметь возможность продолжить работу, получив только:

- адрес репозитория;
- полный SHA последнего коммита;
- указание начать с `AGENTS.md` и `docs/project/PROJECT_STATE.md`.

## 7. Рабочие заметки

`AI_WORK_NOTES.md` используется для проектно значимых заметок, которые ещё не являются утверждёнными решениями. В него можно записывать:

- связь текущего вопроса с другой темой;
- необходимость будущего уточнения;
- потенциальное противоречие;
- граничный сценарий;
- терминологическую проблему;
- влияние решения на другой сервис;
- необходимость пересмотра ранее принятого решения.

Не записывать туда скрытые рассуждения, внутреннюю цепочку мыслей, случайные идеи без проектной ценности или длинные пересказы чата.

## 8. Текущее ограничение

На момент создания этого файла дорожная карта, продуктовые концепции, архитектура и код ещё не формируются. До отдельного указания пользователя следует изменять только документы организации взаимодействия и передачи контекста.
